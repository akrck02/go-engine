3. Undo, several nodes, sharp pixels: an editor to trust

Status: done · Author’s approval: proposal ☑ plan ☑ (2026-10-18, “haz todas pero además haz que aparezca la versión en la ventana de editor y logs”: approved together)

Why

Proposal 2 left four things out on purpose: undo, choosing several nodes, pixel art drawn sharp, and a 3D Level like the 2D one. Without undo, one wrong click loses work. One node at a time makes ten coins ten jobs. Pixel art drawn blurred misleads about how the game looks. And nobody can tell which Go Engine an editor or a game was built with.

What

Id Requirement Check
R1 The editor’s window, its top bar and the logs of the editor, the game and the go-engine command say which Go Engine they run: its release and commit, and whether it is a local copy test the version says which Go Engine it is; test a local Go Engine gives its commit to the build
R2 Every change to the scene can be undone and redone (Ctrl+Z, Ctrl+Shift+Z, and buttons); a drag or a stretch of typing is one step tests a change is undone and redone, a drag is one step to undo

R5 Pixel art is drawn sharp: pictures of a 2D scene are scaled to the nearest pixel, on the desktop and the 3DS a test of go-renderer’s sampling; captures
R6 Level’s tool rail is the same in 3D: Select and Hand, the others greyed capture

Out of scope

  • Undoing changes to sprite and tileset files (Art saves them itself).
  • Choosing several nodes by dragging a box.

Design

Version (done first): engine.Version() reads the program’s build information. For a local copy (a go.work or a folder replace), go-engine passes the commit with -ldflags -X.

Undo: the editor keeps the scene’s description after each change, in a list with a place in it. Undo builds the scene again from the one before, keeping the chosen nodes by path. Changes within half a second of each other are one step, so a drag or typing a number is undone at once.

Several nodes: Editor.Chosen holds the nodes besides Selected, the one the inspector shows.

Sharp pixels: go-renderer’s 2D pictures get a filter setting. A 2D scene draws its sprites and tiles with the nearest pixel. That change belongs to go-renderer, on its feature/3ds branch, committed only with the author’s say.

Result

Built.

  • The version of Go Engine shows in the editor’s title and top bar. The logs of the editor, the game and the go-engine command say it too, with the commit of a local copy and whether it has changes.
  • Undo and redo of every change to the scene. A drag or a number typed is one step.
  • Several nodes chosen with Shift, then dragged, deleted and duplicated together.
  • Tests that press, move and let go the mouse over the 2D view.
  • Level’s tool rail in 3D (Select and Hand).
  • Pixel art drawn sharp, through go-renderer’s draw2d.Image.Sharp (feature/3ds 3b08cd9, committed with the author’s say). The engine sets it on every sprite, frame and tile.

Checked. Every task’s tests pass. Sharp pixels were compared before and after in captures, on the desktop and in the 3DS emulator.

Not done. Metal draws sharp pictures blended, as before: it is hand-written and was not touched. Changes to sprite and tileset files are not undone (Art saves them itself). Choosing nodes with a box was out of scope.

For a person. Undo after real edits, Shift-clicks and drags with a real mouse.
