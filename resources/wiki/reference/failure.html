failure

import "github.com/akrck02/go-engine/failure"

Package failure gives every error go-engine returns a code: a stable name, as “engine.scene-not-found”, that a program can check and a person can search for.

A code is declared once, as a package-level variable, and is itself an error:

var SceneNotFound = failure.Define("engine.scene-not-found", "the scene file does not exist")

Returning the code alone allocates nothing and comparing it is comparing two pointers, as cheap as Go’s own sentinel errors. When the error needs its details (which file, what went wrong underneath), Wrap makes one error with them; that happens while loading or building, never in a game’s frame.

Callers check an error by its code, wrapped or not:

if failure.Is(err, engine.SceneNotFound) { … }

errors.Is works the same way, since an error made by Wrap answers to its code.

Error

Error is a coded error with its details: what the code means here, and the error underneath.

type Error struct {
	Code    *Code
	Details string // what is particular to this error: a file, a name
	Cause   error  // the error underneath, if any
}
Function or method
